🚢 GitHubの一般的なデプロイ方法

作ったコードをインターネットに公開するための、代表的な方法をまとめました

📌 そもそも「デプロイ」とは？

デプロイ（Deploy）とは、作ったコードを実際にインターネット上で動かせる状態にすることです。 GitHubにコードを置くだけでは、まだ「保管しているだけ」の状態。デプロイして初めて、他の人がブラウザからアクセスできるようになります。

コードを書く → GitHubにPush → デプロイ → 公開URL完成

🌐 方法1：GitHub Pages（もっとも手軽）

静的サイト向けの無料ホスティング

HTML・CSS・JavaScriptだけで作られたサイト（ブログ、ポートフォリオ、ドキュメントなど）を、GitHubが無料で公開してくれる機能です。サーバーの用意は不要。
設定手順：
  1. リポジトリの Settings → Pages を開く
  2. 公開元（Source）を選ぶ（mainブランチ、または GitHub Actions）
  3. 数分待つと https://ユーザー名.github.io/リポジトリ名/ で公開される
向いているもの： ブログ、ドキュメントサイト、ポートフォリオ、フロントエンドだけのミニアプリ
向いていないもの： データベースが必要なアプリ、サーバー側の処理（PHP、Pythonのバックエンドなど）

⚙️ 方法2：GitHub Actions で自動デプロイ

「Pushしたら自動で公開」を実現する仕組み

GitHub Actionsは、特定の操作（例：mainブランチへのPush）をきっかけに、自動でテスト・ビルド・デプロイまで行ってくれる仕組みです。 リポジトリ内に .github/workflows/ フォルダを作り、設定ファイル（YAML）を置くだけで動きます。
name: Deploy to GitHub Pages on: push: branches: - main jobs: deploy: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/configure-pages@v5 - uses: actions/upload-pages-artifact@v3 with: path: . - uses: actions/deploy-pages@v4
メリット： 一度設定すれば、以降は git push するだけで自動的に最新版が公開されます。手動でのアップロード作業が不要になります。

☁️ 方法3：外部ホスティングサービスと連携

Vercel / Netlify / Renderなど

GitHubリポジトリと外部サービスを連携させることで、より高機能なデプロイ（サーバー処理、環境変数、独自ドメインなど）が可能になります。
サービス 得意なこと
Vercel Next.js等のフロントエンドアプリに強い。Push即デプロイ。
Netlify 静的サイト・JAMstackに強い。フォーム機能等も充実。
Render / Railway バックエンドサーバーやデータベースが必要なアプリ向け。
基本的な流れ：
  1. サービスにGitHubアカウントでログイン
  2. デプロイしたいリポジトリを選択
  3. ビルド設定（自動検出されることが多い）を確認
  4. 以降は git push するたびに自動でデプロイされる

🔑 覚えておきたい共通の流れ

どの方法を選んでも、基本的な考え方は同じです。
  1. ブランチで作業する - 直接mainを触らず、featureブランチで変更する
  2. Commit & Push する - 変更内容を記録してGitHubに送る
  3. Pull Requestでレビュー - 問題ないか確認してからmainにマージ
  4. mainへのマージがトリガーになる - 多くのサービスは、mainブランチへの変更を検知して自動デプロイする
ポイント： 「デプロイ＝Push」ではなく、「Pushがきっかけでデプロイが走る」というのが正しい理解です。設定なしにPushしただけでは何も公開されません。

📊 方法の選び方まとめ

作りたいもの おすすめの方法
ブログ・ポートフォリオ・ドキュメント GitHub Pages
