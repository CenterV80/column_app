🧠 生成AI用語

画像・動画生成AIの記事でよく見かける用語をやさしく解説します

蒸留（じょうりゅう / Distillation）

大きく高性能な「先生」モデルの出力を真似するように、小さな「生徒」モデルを学習させる技術です。性能をなるべく維持したまま、モデルを軽量化・高速化するのが目的です。
画像・動画生成AIでは、本来何十ステップもかけて生成する処理を、蒸留によって数ステップまで減らしたモデルがよく登場します。生成が速くなる分、計算コストや待ち時間が大きく下がります。
例： LTX-2.3の「蒸留2段階パイプライン」は、通常より少ないステップ数で高速に動画を生成できるように蒸留されたモデルです。

量子化（りょうしか / Quantization）

モデルの重み（パラメータ）を、より少ないビット数の数値で表現し直す技術です。通常は32bitの浮動小数点数で保存されているところを、16bit・8bit・4bitなどに圧縮します。
ビット数を減らすことで、モデルのファイルサイズとVRAM（メモリ）使用量を大幅に削減できます。その結果、性能が低いPCやGPUでも大きなモデルを動かせるようになります。精度がわずかに落ちることもありますが、影響の少ない部分を選んで圧縮するのが一般的です。
32bit（フル精度）約24GB → 量子化 → 8bit・4bitなど 約7〜13GB

ビット数を削るほど、ファイルサイズとVRAM使用量が小さくなる

量子化にもやり方の違いがあり、代表的なのがfp8とGGUFです。
方式 中身 特徴
fp8 8bitの浮動小数点数 GPUのTensorコアでそのまま高速演算できる。diffusersとの相性が良い
GGUF（Q8 / Q4など） 8bit・4bitなどの整数 ファイルはより小さいが、計算前に逆量子化する専用ローダーが必要
例： 「Q4」「Q8」といった表記のモデルファイルは、それぞれGGUF形式で4bit・8bitに量子化されたバージョンを指します。

pruned（プルーンド / 刈り込み済み）

学習時にだけ必要だった余分なデータを削り、配布用に軽くしたチェックポイントファイルのことです。「prune」は庭木の剪定という意味で、モデルを剪定して身軽にするイメージです。
フル版（学習用の余剰データ入り） ✂️ pruning → pruned版（配布・利用専用）

生成に使わないデータだけを削るので、出力結果は変わらない

これは主にSD1.5世代でよく見られた文化です。SDXLやFluxなど新しい世代の公式配布ファイルは、最初から生成に必要な分だけで作られていることが多く、pruned版がほとんど存在しません。軽量化の主流も、pruning（剪定）から量子化へと移ってきています。
ポイント： 「pruned」の表記がないからといって、そのモデルが重いとは限りません。世代によって配布のされ方自体が違うだけです。

テキストエンコーダー（Text Encoder）

入力したプロンプト（文章）を、AIが扱える数値の並び（embedding）に変換する役割のモデルです。ここで作られた数値が、絵を描くU-Netに「何を描くか」を伝える設計図になります。
プロンプト（文章） → テキストエンコーダー → 数値ベクトル（embedding）

この数値ベクトルがU-Netに渡り、生成内容を誘導する

代表例は画像・テキストのペアで学習されたCLIPですが、テキストエンコーダーはCLIPだけではありません。SDXLはCLIP ViT-LとOpenCLIP ViT-bigGという2つのテキストエンコーダーの出力をつなげて使うことで、より豊かな表現を実現しています。
ポイント： テキストエンコーダーはcheckpointファイルの中に含まれているのが一般的で、多くの場合は別途ダウンロードしたり容量を気にしたりする必要はありません。

checkpoint（チェックポイント）

画像を生成するために必要な部品一式を、1つのファイルにまとめたものです。「モデルファイル」と呼ばれることも多く、これ1つをロードするだけで生成が始められます。
checkpointファイル
U-Net（絵を描く本体） + VAE（画像⇔潜在空間の変換） + テキストエンコーダー

これらが1つのファイルに同梱されている

例： 「SDXL baseのcheckpoint」と言えば、U-Net・VAE・2つのテキストエンコーダーがまとめて入った、約6.5GBの1ファイルを指します。

LoRA（ローラ / Low-Rank Adaptation）

巨大なベースモデル本体はそのままに、小さな追加ファイルだけで絵柄やキャラクターを追加学習させる手法です。ベースモデルが数GB〜数十GBあるのに対し、LoRAファイルは数十MB程度と非常に軽量です。
ベースモデル（数GB〜） + LoRA（数十MB） → 追加学習された絵柄・キャラクター

ベースモデル本体を書き換えず、差分だけを軽い追加ファイルとして持てる

例： 「Turbo LoRA」は、通常より少ない生成ステップ数で速く生成できるようにする追加ファイルです。

ControlNet と OpenPose

ControlNetは、プロンプト（文章）だけでは伝えづらい構図・ポーズ・輪郭線などを、画像のような「ガイド」を渡すことでAIに正確に伝える仕組みです。
プロンプトのみ → ポーズや構図はAI任せ
プロンプト + ControlNetガイド（骨格など） → 狙い通りのポーズ・構図
OpenPoseは、そのガイドの代表的な種類のひとつで、人体の関節位置を線でつないだ「棒人間」形式のポーズ情報です。ControlNetにOpenPoseのガイドを渡すことで、指定したポーズ通りの人物を生成できます。
例： 「SDXL+ControlNet OpenPose」は、SDXLで絵を描きつつ、OpenPose形式の棒人間でポーズを指定する構成を指します。
