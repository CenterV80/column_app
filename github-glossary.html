🚀 GitHub初心者向け用語辞典

困ったときに読む、わかりやすいGit用語解説

📚 初心者向け基本用語

Repository（リポジトリ / レポジトリ）

プロジェクトのデータを保存する場所です。GitHubでは1つのプロジェクト = 1つのリポジトリ。ファイルの変更履歴がすべて記録されています。
例： column_app というリポジトリは、このプロジェクトのすべてのコードを管理しています。

Commit（コミット）

現在のコードの状態を「スナップショット」として保存する操作です。何が変わったのか、なぜ変わったのかをメッセージとセットで記録します。
git commit -m "ログイン機能を追加"
重要： Commitだけではリモート（GitHub）に保存されません。次のPushが必要です。

Push（プッシュ）

ローカル（自分のパソコン）のCommitをGitHubに送信する操作です。
git push origin main
イメージ： Commitが「下書きを保存」だとすると、Pushは「みんなに見せる投稿」です。

Pull（プル）

GitHubのコードを自分のパソコンにダウンロードする操作です。チームメンバーが新しいコードをPushした場合、自分のパソコンに反映させるために使用します。
git pull origin main

Branch（ブランチ）

コードの「枝分かれ」です。メインのコード（main/master）から別の枝を作って、そこで新機能や修正を行うことができます。
git branch feature/new-login
git checkout feature/new-login
イメージ： 元の作品を保護しながら、別の版で実験できる感じです。

Clone（クローン）

GitHubのリポジトリを自分のパソコンにコピーする操作です。初めてプロジェクトに参加するときに使用します。
git clone https://github.com/user/project.git
Clone後： プロジェクトのすべてのファイルと変更履歴があなたのパソコンに保存されます。

Fork（フォーク）

他の人のリポジトリを、自分のGitHubアカウントにコピーすることです。元のプロジェクトに影響を与えずに、自分で自由に編集できます。
使われる場面：
  • オープンソースプロジェクトに貢献したいとき
  • 他人のプロジェクトをベースに新しい作品を作りたいとき

Pull Request（PR）

「このコードを本体に統合してください」というリクエストです。自分が作った機能や修正を、メインのコードに取り込んでもらうために使います。
流れ：
  1. Forkまたはbranch作成
  2. コードを変更してPush
  3. Pull Request作成 → レビュー → Merge
GitHub上で行う操作： コードの議論やレビューが全部PRのページで行われます。

Merge（マージ）

異なるBranchを統合する操作です。Pull Requestが承認されると、マージされてメインのコードに反映されます。
イメージ： 別に書いていた文章を、元の原稿に合体させる感じです。

🎓 中級者向け用語

Fetch（フェッチ）

GitHubから最新情報をダウンロードしますが、ローカルのコードには反映させません。Push後に他のメンバーが何をしたのか「確認だけしたい」ときに使用します。
git fetch origin
PullとFetchの違い：
Fetch 情報を取得するだけ
Pull 情報を取得 + ローカルに反映（Fetch + Merge）

Checkout（チェックアウト）

別のBranchに切り替える操作です。
git checkout feature/new-login
新しいBranchを作成して切り替える：
git checkout -b feature/new-feature

Diff（ディフ）

ファイルの変更内容を表示する操作です。何が追加されて、何が削除されたかを確認できます。
git diff

Tag（タグ）

重要なCommitに「目印」をつける操作です。バージョンリリースのときなどに使用します。
git tag v1.0.0
git push origin v1.0.0

Stash（スタッシュ）

作業中のコードを一時的に保存する操作です。Commit前に別のBranchに切り替えたいときに便利です。
git stash # 現在の変更を保存
git stash pop # 保存した内容を復元

🔬 上級者向け用語

Rebase（リベース）

Commitの歴史を再構成する操作です。複数のCommitを1つにまとめたり、Commitの順序を変更したりできます。
git rebase -i HEAD~3
注意： 既にPushしたCommitをRebaseするのは危険です。

Cherry-pick（チェリーピック）

特定のCommitだけを別のBranchに適用する操作です。全部のCommitではなく、必要な変更だけを取ってくる場合に使用します。
git cherry-pick abc123

Reflog（レフログ）

あなたのすべての操作の履歴です。うっかり削除したBranchやCommitを復元するときに使用します。
git reflog

Bisect（バイセクト）

バグの原因になったCommitを自動検索する操作です。大量のCommitの中からバグの原因を特定するときに便利です。
git bisect start

Hook（フック）

特定の操作の前後に自動実行される処理です。Commitしてくるコードの品質チェックなどに使用されます。
例： pre-commit hook が動いて、自動的にコードをチェックしてからCommitさせる。

Squash（スクワッシュ）

複数のCommitを1つにまとめる操作です。Pull Requestをマージするときに「Squash and merge」を選択して使用します。

📖 Git vs GitHub

Git バージョン管理システム（ローカルで使う）
GitHub Gitを使ったクラウドサービス（オンラインで共有）
