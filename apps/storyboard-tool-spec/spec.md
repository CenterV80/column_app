# 絵コンテ生成ツール 技術仕様書

## 1. 概要

字コンテから絵コンテを生成し、動画生成AIに渡すためのプロンプトと参照画像のセットを出力するWebアプリケーション。

**シーン単位で作業するツール。** 字コンテの入力、アンカーの配置、コマの生成、書き出しまで、すべてシーン1本の中で完結する。

### 基本フロー

1. シーンの字コンテを書く
2. 字コンテから「時間経過だけを示したプロンプト行」が生成される
3. プロンプト行にアンカーを打つ（カットアンカー／コマアンカー）
4. アンカーで区切られた区間ごとにラフスケッチのコマが生成される
5. 各コマに自由文で修正指示を出して詰める
6. カット単位で「動画プロンプト＋コマ画像＋キャラクターシート」を書き出す

---

## 2. 用語と階層

| 階層 | 定義 |
|---|---|
| プロジェクト | 作品全体。シーンを束ねるだけの入れ物 |
| シーン | 同じ場所・同じ時間軸のまとまり。**作業単位** |
| カット | シーン内のカメラの切り替わり。**動画プロンプト1本に対応** |
| コマ | カット内の絵。1枚のことも、動きを示すため複数枚のこともある |

**制約:** カットの境界は必ずコマの境界を兼ねる。カットをまたぐコマは存在しない。

キャラクターシートは**シーンに紐づく**。複数シーンでの共有はしない（別シーンからのコピー導線のみ用意する）。

---

## 3. データモデル

### Project

```
id
name
```

### Scene

```
id
projectId
name          表示用。日本語可
slug          ASCII。書き出しファイル名に使う
order
```

`name` はファイル名に使わない。書き出し名は必ず `slug` から作る。

### ScriptBlock（字コンテ）

```
id            UUID。テキストを書き換えても不変
sceneId
order
text
```

字コンテはブロックエディタ形式。1行＝1ブロック。**アンカーはこのIDを起点に解決されるため、IDの安定性が設計の要。**

### PromptLine（時間経過プロンプト行）

```
id
sceneId
sourceBlockId   生成元の ScriptBlock
order
text
```

ScriptBlock 1件から 1〜N件が生成される。再生成は親ブロック単位で行う。

### Anchor

```
id
sceneId
promptLineId    この行の頭に刺さる
type            'cut' | 'frame'
```

### Cut

```
id
sceneId
order
videoPrompt       動画生成AIに渡すテキスト
readingNote       このカット固有の「絵コンテの読み方」
duration          nullable。null = AIに尺を任せる
durationSource    'manual' | 'estimated' | null
```

### Frame（コマ）

```
id
cutId
order
structuredPrompt  下記参照
dirty             要更新フラグ
```

### StructuredPrompt

**画に出るフィールド**（画像生成に渡す）

```
shot           ロング / ウエスト / アップ など
angle          アイレベル / 俯瞰 / 煽り
characters[]   { sheetId, position, expression, pose }
action         何が起きているか
place          場所・背景
light          時間帯・光
```

**画に出ないフィールド**（紙面表示と読み方テキストの材料）

```
camera         FIX / PAN / TU など
dialogue       セリフ
se             効果音
note           演出メモ
```

画に出ないフィールドは**画像生成プロンプトに混ぜない**。混ぜると文字や矢印が画に描き込まれる。

### FrameImage

```
id
frameId
storagePath
createdAt
isSelected
```

バージョンは削除しない。すべて残す。

### CharacterSheet

```
id
sceneId
handle         'chara1', 'chara2' … 自動採番
displayName    任意
storagePath
```

**handle は採番後に変更しない。削除しても番号を再利用しない。** 字コンテや修正指示に文字列として残るため、付け替えると過去の指示が壊れる。

## 4. 字コンテ編集時の再生成ルール

字コンテはいつでも自由に編集できる。アンカーは行番号ではなくブロックIDを起点に解決されるため、編集でコマが消えることはない。

| 操作 | 挙動 |
|---|---|
| ブロック内を書き換えた | そのブロック由来の PromptLine だけ再生成。前後ブロックは文脈として渡すだけで書き換えない |
| ブロックを追加した | 挿入位置に行が増える。既存アンカーは無傷。増えた区間のコマだけ `dirty` |
| ブロックを削除した | 由来する行を削除。刺さっていたアンカーは直前のアンカーに吸収され、コマが1つ減る |

**再生成された行にアンカーが刺さっていた場合、該当コマは `dirty = true` にするだけで、画像は自動再生成しない。** カードにバッジを出し、ユーザーが更新を叩いたときだけ絵が変わる。勝手に絵が変わるとレビューが成立しない。

---

## 5. 画風の方針

**絵コンテの絵は、動きと構図を動画生成AIに伝えるための指示書であり、完成画ではない。** 清書された絵を出すと、動画生成がそれを最終画として再現しようとする。

したがって、鉛筆で雑に描いたようなラフスケッチであることが機能要件になる。

- 画風はシステム側に固定文字列として持つ。**ユーザーが触れるフィールドにはしない**
- キャラクターシートの画風を引きずらないよう、参照画像は人物の同定にのみ使う旨をプロンプトに明記する
- ラフでは顔の造形は再現されない。**識別は髪型・体型・服装で行われる**前提でシートを用意する
- 矢印・記号の類は描かせない。プロンプトに明示的に禁止を入れる（指示しないと勝手に描く）

カメラワークは画に描かず、読み方テキストに文章として渡す。

---

## 6. コマの修正フロー

1. ユーザーが自由文で指示する（例:「もっと寄って、不安そうな顔に」）
2. LLMが `structuredPrompt` の**差分JSONだけ**を返す
   - `shot: ウエスト → アップ`
   - `characters[0].expression: 無表情 → 不安`
3. 差分を画面に表示し、ユーザーが承認
4. 承認後に画像生成

差分を挟むことで、修正が効かなかったときに「プロンプトが変わっていないのか、絵が言うことを聞かないのか」を切り分けられる。差分指示を画像に直接積み上げる方式は破綻するため採らない。

### 生成モードは2つ

| ボタン | 挙動 | 用途 |
|---|---|---|
| 直す | 元画像＋指示で編集 | 表情、小物、手の位置 |
| 描き直す | 更新後プロンプトから再生成 | カメラ、アングル、コマの意味が変わるとき |

マスク指定のインペイントは初版では実装しない。

---

## 7. キャラクターシート

- 画像をアップロードし、ハンドルを自動採番する
- 表示名は任意（空でも動作する）
- 字コンテや修正指示では `chara1` の形で参照する
- 字コンテ入力中に `@` でサムネイル付きの候補を出し、選択で挿入する

**`chara1` という文字列をそのままモデルに渡さない。** アプリ側で解決してから渡す。キャラ名と誤解されて画に文字が出る。

| 場面 | 解決先 |
|---|---|
| 字コンテ中 | プロンプト生成時に `characters[].sheetId` に変換 |
| 修正指示中 | 差分JSONの対象を特定 |
| 画像生成時 | 該当シート画像を参照添付 |

参照添付は実用上2体まで。3体を超えると顔が混ざる。3体以上が映るコマは、主要2体だけシートを添付し、残りは文章で記述する。

## 8. 画面構成

### コマ一覧（レスポンシブなカードグリッド）

```css
grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
```

列数はブラウザに任せ、JSで測らない。折り返しは左から右、次の行へのZ順。列読みは列数が変わると順序が変わるため採らない。

カードに載せるもの（優先順）

1. コマ番号
2. スケッチ画像（`aspect-ratio: 16/9` で最初から枠を確保）
3. セリフ（2行でクランプ）
4. 尺 ＋ カメラワークのバッジ
5. 要更新バッジ（あるときだけ）

`action` や `place` はカードに出さない。280px幅で読めなくなる。

**未生成のコマも同じ高さのカードで並べる。** 生成済みだけ高さが変わると、一括生成中にグリッド全体がガタつく。

カードのキーには **Frame の ID を使う**。indexをキーにするとアンカー追加時に全カードが再描画される。

### コマ詳細

カードをタップで全画面モーダル。構造化プロンプトの編集、修正指示の入力、バージョン履歴を扱う。

## 9. 尺（duration）

Cut が持つ。nullable。

- 空欄 ＝ 動画生成AIに尺を任せる
- 入力あり ＝ 尺を指示する

| 用途 | 扱い |
|---|---|
| コンテ紙面 | 空欄はそのまま空欄。「—」も入れない |
| 合計尺 | 入力済みのみ合計し「うち3カット未指定」と併記。全部埋まらないと合計が出ない作りにしない |
| 動画生成への受け渡し | 空欄はキーごと落とす。`duration: null` は「尺ゼロ」と解釈されうる |

`durationSource` で手入力と推定を区別する。推定値は薄いグレー表示。「尺を見積もる」ボタンは**空欄だけ埋め、手入力済みは上書きしない**。

## 10. 保存

### 自動保存

シーンの現在状態を常時保存する。デバウンス1〜2秒。復帰時は最後の状態をそのまま開く。「保存しました」は表示しない。

### スナップショット

シーンのその時点を丸ごと固定し、名前を付けて残す。

保存対象

- ScriptBlock 全件
- PromptLine 全件
- Anchor の位置（両種）
- Cut / Frame の構造
- 各 Frame がその時点で採用していた **FrameImage の ID**

**画像の実体はコピーしない。参照IDのみ持つ。** そのかわり FrameImage は削除しない。復元時に参照先が消えているのが最悪の壊れ方。

### 自動スナップショット

以下のタイミングで自動取得する。手動と同じリストに並べ、自動は薄く表示する。名前が付くのは手動のみ。

- 全コマ一括生成の直前
- 字コンテを大きく書き換えた直後
- 書き出しの直前

### 復元

破壊的にしない。**現在状態を新しいスナップショットとして自動退避してから戻す。** 復元後は通常どおり自動保存が継続する。

## 11. 書き出し

カット単位で、動画生成AIにそのまま投入できる形にする。ZIPで出力。

### ファイル構成

```
scene01.json
scene01_chara1.png
scene01_chara4.png
scene01_cut03_01.png
scene01_cut03_02.png
```

- 接頭辞は Scene の `slug`
- コマ画像はカット番号＋カット内連番。通し番号にせず階層を残す
- キャラクターシートは**そのシーンに実際に登場する分だけ**同梱する。`characters[].sheetId` を集めれば自動で決まるため、ユーザーに選ばせない

### JSON

```
{
  scene: { slug, name },
  characters: [ { handle, file } ],
  cuts: [
    {
      order,
      videoPrompt,
      readingNote,
      duration,        // 未指定ならキーごと省略
      frames: [ "scene01_cut03_01.png", ... ]
    }
  ]
}
```

### 読み方テキスト

絵コンテ画像も動画生成AIに渡すため、読み方を添える。2階層で持つ。

| 階層 | 内容 |
|---|---|
| 共通の読み方 | 画風の説明、線の意味、ラフである理由。プロジェクト固定のテンプレート |
| カット固有 | このカットで何を参照してほしいか。カメラワークもここに文章で書く |

書き出し時に、共通ぶんを各カットの `readingNote` の先頭へ連結する。**テンプレートは編集可能にする。** 動画生成モデルを変えると効く文言が変わるため。

## 12. 技術スタック

| 領域 | 採用 |
|---|---|
| 開発・デプロイ | Google AI Studio → Cloud Run |
| 構造データ | Firestore |
| 画像 | Cloud Storage |
| 認証 | Firebase Authentication |
| テキスト生成 | Gemini（プロンプト行生成、差分JSON生成、尺推定） |
| 画像生成 | `gemini-3.1-flash-image`（Nano Banana 2） |

画像を Firestore に直接入れない。1MB制限に当たる。バージョン込みで枚数が膨らむため、保存先の分離は必須。

## 13. 未決事項

実装に着手してから詰める。

- **生成の実行制御** — 全コマ一括生成時の並列数、順序、Gemini APIのレート制限への対処、途中失敗時のリトライ
- **失敗時の表示** — 生成エラー、安全フィルタによるブロック、参照画像の顔崩れをカードにどう出すか
- **認証の要否** — 個人利用なら Firebase Auth を省略できるか。Cloud Run のURLが外部から到達可能な点をどう扱うか
- **セリフの扱い** — `dialogue` を動画生成に渡すと喋らせようとする可能性がある。読み方テキストに含めるか除外するか
