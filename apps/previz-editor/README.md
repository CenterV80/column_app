# プレビズエディタ — コードの説明

生成動画AI向けのカットを、箱のキャラクターとカメラで先に組み立てるツール。
ブラウザだけで完結する。サーバーもビルドもフレームワークも使っていない。

公開先: `https://<ユーザー名>.github.io/column_app/apps/previz-editor/`

---

## ファイル構成

| ファイル | 中身 | 規模 |
|---|---|---|
| `index.html` | 画面の骨組みとアイコン定義 | 157行 |
| `style.css` | 見た目 | 640行 |
| `app.js` | **本体。ロジックはほぼ全部ここ** | 2,399行 |
| `vendor/three.min.js` | 3D描画（three.js r128, MIT） | 同梱 |
| `vendor/mp4-muxer.js` | MP4を組み立てる（MIT） | 同梱 |
| `vendor/webm-muxer.js` | WebMを組み立てる（MIT） | 同梱 |
| `vendor/*.LICENSE` | 上記2つのライセンス | — |

JSONはコードではなく**保存形式**。使うのは自動保存・シーン書き出し・読み込みの3か所だけ。

### なぜ vendor に同梱しているか

CDNから読むと、回線制限のある環境やオフラインで真っ黒な画面になる。
同梱しておけば、フォルダごと落として `index.html` を開くだけで動く（`file://` で動作確認済み）。
ムーサ2つは起動時には読まず、**動画を書き出すときだけ**読み込むので初期表示は軽いまま。

## app.js — 本体

全体が1つの即時関数（IIFE）に包まれていて、グローバルを汚さない。
以下、セクション順に役割を書く。

### 1. 定数

- `COLORS` — 赤→青→緑→黄。追加順に割り当てて循環する
- `KIND` — キャラの種別（ひと／巨人／竜）ごとの当たり判定・注視点の高さ・立ち位置の間隔
- `col()` — **sRGBの色をリニアに変換する**。three r128 は色空間を自動変換しないので、これを通さないと全部白っぽく浮く
- `lensToFov()` / `fovToLens()` — レンズのmmと画角の相互変換（フルサイズ36mm幅を16:9で切った前提）

### 2. 状態（`state`）

アプリの状態は全部このオブジェクトに集約している。

```
fps, duration, current      時間まわり（すべてコマ単位）
playing, loop, ease         再生の設定
trails, grid, autoFace      表示・挙動の設定
view                        "editor" か "camera"
mode / camMode              いま選んでいる道具
objects[]                   いま開いているカットの中身（カメラ・キャラ・めじるし）
shots[] / shotIndex         カットの一覧と、いま開いている番号
selectedId, nextId          選択と採番
```

**カットの持ち方には方針がある。**

- `objects[]` は「いま開いているカット」だけを three.js のオブジェクトとして持つ
- ほかのカットは `shots[]` にシリアライズした形で眠っている
- 切り替えは `serializeShot()` で控えて `loadShot()` で組み立て直す

つまりシーンに存在するのは常に1カット分だけ。カットが増えても描画は重くならない。

| どちらに属するか | 項目 |
|---|---|
| カットごと | 長さ・オブジェクトの配置とアニメ・注視先 |
| 全体で共通 | fps・補間・進む向き設定・表示設定 |

### 3. three 基本

レンダラ・シーン・ライト・床・マス目・軌跡・選択リング・注視マークの用意。

- **フォグの色は `col()` を通さない。** three r128 のフォグは sRGB に直したあとで混ざるため、
  変換すると地平線に暗い帯が出る（背景の値をそのまま渡す）
- 注視マークだけ `depthTest:false` で手前に描く。相手の体に埋もれて見えなくなるため
  （選択リングは足元に置くので通常描画のまま）

### 4. リグ生成

見た目を組み立てるところ。全部プリミティブ（箱・四角錐）で作る。

| 関数 | 作るもの |
|---|---|
| `frontCone()` | 正面を示す白い四角錐。頂点が +Z を向くようジオメトリ側で寝かせてある |
| `slab()` | 箱を1つ置くだけの短縮関数 |
| `buildCharacter()` | 種別で振り分ける入口。人型はここで組む |
| `buildGiant()` | 巨人（約4.4m・脚と腕つき） |
| `buildDragon()` | 竜（胴・首・頭・角・翼・4本脚・尾） |
| `buildProp()` | 背景のめじるし。**全部おなじ大きさ**なので見えた大きさが距離になる |
| `buildCamRig()` | カメラの本体と四角錐のワイヤー |
| `hitProxy()` | 見えない当たり判定。`material.visible=false` は描画されないがレイキャストには当たる |

**リグの階層には意味がある。**

```
root          ← キーフレームが書かれるのはここだけ
 └ fx         ← プルプルや登場アニメはここを揺らす（データは汚れない）
     └ 各パーツ
 └ hitProxy   ← 揺れの外側。揺れても的が動かない
```

### 5. オブジェクト管理

- `addCharacter()` / `addProp()` / `addCamera()` — 追加。`state.objects` に同じ形で入れる
- `freeSpot()` — 既存のものと重ならない立ち位置を探す（互いの大きさを見る）
- `aimCamera()` — 注視中にカメラを相手に向ける。**操作のときだけ呼ぶ**
- `setLookAt()` — 注視の入り切り
- `orbitStateOf()` / `applyOrbit()` / `clampPhi()` — 相手を中心にした回り込み。
  上下は高さではなく**角度の側**で止める（高さで止めると距離が変わってしまう）

### 6. キーフレーム

このアプリの心臓部。

| 関数 | 役割 |
|---|---|
| `readKey()` | いまの姿勢をキーの形に読み出す（位置・回転・レンズ） |
| `autoKey()` | **触ったら自動で現在フレームに記録する。** めじるしは対象外 |
| `deleteKeyAt()` | キーを消す。最低1つは残す |
| `sample()` | ある時間の姿勢を計算する。角度は近い方の回り方で補間 |
| `applyFrame()` | 全オブジェクトをその時間の姿勢にする |
| `lerpAngle()` | 359°→1° を 358°分回さずに 2°分で回すための補間 |

**記録の原則: 触った時間のキーだけを書く。ほかの時間には絶対に触らない。**
注視点は「操作のしかたを変えるだけ」で、再生中に向きを上書きしたり、
解除時に全キーを書き換えたりはしない。そうしないと入り切りのたびにカット全体が変わってしまう。

### 7. 更新フラグ

`markDirty()` を呼ぶと「軌跡の引き直し」「タイムラインの作り直し」「保存」の予約が立つ。
実際の処理は描画ループ側でまとめて行い、ドラッグ中は間引く。

### 8. プルプル

つかんでいる間キャラが嫌がって震える。`fx` グループだけを揺らすのでデータは汚れない。
減衰は**実時間**で進める（描画が遅い端末で揺れが長く残らないように）。

### 9〜10. 画面レイアウトと描画ループ

- `layout()` — canvasのサイズ合わせと、カメラ視点の16:9をどこに描くかの計算。
  上のバーと下のタイムラインに隠れない範囲に収める
- `tick()` — 毎フレーム。再生・プルプル・引き直し・描画。
  **動画の書き出し中はここを止める**（1コマずつこちらで描くため）

### 11. 再生・時間

`setFrame()` が時間移動の唯一の入口。姿勢の適用・時間表示・再生ヘッド・キーの強調をまとめて行う。

### 12. ビューポート操作

指とマウスの担当。

| 関数 | 役割 |
|---|---|
| `pickObject()` | **見えている面を最優先で拾う。** 当たらなかったときだけ当たり判定に頼る |
| `ownerOf()` | 当たったメッシュから持ち主のオブジェクトを辿る |
| `pickInFrame()` | カメラ視点で画の中のキャラを指す（16:9の枠内の座標に直す） |
| `onPointerDown/Move/Up` | 操作の入口。1本指・2本指・カメラ視点で分岐 |
| `applyObjectDrag()` | 道具に応じて移動・高さ・向きを変える。移動中は進む向きに体を向ける |
| `shiftCamera()` | カメラを画面と平行にずらす。被写体までの距離に合わせるので指の動きと画が噛み合う |

**拾い方には理由がある。** 当たり判定だけで判断すると、手前のキャラの見えない箱が
奥のキャラを隠してしまい、クリックした色と違うものが選ばれる。
カメラの枠線も除外している（three.jsの線は既定で半径1m相当の判定を持つため）。

### 13. 選択バッジ

選択中のものの表示と、道具バーの出し分け。
上下の傾きはカメラにしかないので、キャラを選んでいる間は隠す。

### 14. タイムライン

目盛り・トラック・キーの描画と、スクラブ／キーのドラッグ。

- キーを**上下にはらうと消える**。レーンの高さより大きい34pxを超えたときだけ「離せば消える」状態に入る
- その間は行が赤く光り、指を戻せば元通り。消したあとも5秒間「もどす」で戻せる
- めじるしは行を持たない

### 15. 書き出し（文章・画像・シーン）

- `shotText()` — カメラと人の動きを日本語の文章にする
- `promptDraft()` — 英語プロンプトのたたき台（dolly in / truck right などに言い換える）
- `serialize()` / `loadScene()` — シーンのJSON化と復元
- `capturePng()` — 1280×720のPNG。補助表示は映さない

### 16. 動画の書き出し

| 関数 | 役割 |
|---|---|
| `pickVideoFormat()` | 使える形式を上から試す。H.264が使えればMP4、だめならWebM |
| `loadScriptOnce()` | ムーサを必要になってから読み込む |
| `exportVideo()` | 1コマずつ描いて符号化し、ファイルに組み立てる |
| `depthRange()` | デプス映像の濃淡の範囲。**カット全体から先に決める**のでちらつかない |
| `depthMat` | デプス用シェーダ。近いほど白く、**距離の逆数**で割り当てる |

**画面録画ではなく1コマずつ符号化している。** そのため端末が遅くてもコマ落ちせず、
fpsと尺が指定どおりになり、実時間を待つ必要もない。

デプスで距離の逆数を使うのは、そのままの距離だと遠くのものに引っ張られて
手前の被写体が真っ白に潰れるため。

### カットまわりの関数

| 関数 | 役割 |
|---|---|
| `serializeShot()` | いま画面に出ているカットを保存できる形に落とす |
| `loadShot()` | 保存した形からカットを組み立て直す |
| `switchShot()` | いまの内容を控えてから、別のカットを開く |
| `addShot()` | **いまのカットを複製して足す**（セットとキャラを引き継げる） |
| `removeShot()` | カットを消す。「もどす」で戻せる。最後の1つは消せない |
| `renderShotBar()` | ドック上部のカットのチップを描く |

### 17〜19. シート・設定・初期化

- `openSheet()` — 書き出しと使い方の共通の枠
- `syncSettings()` / `setDuration()` — 設定の反映。fpsを変えても秒での見え方が変わらないようキーごと伸縮させる
- `defaultScene()` — 初期配置（カメラ・ひと2人・めじるし8本）
- `bind()` — イベント登録を1か所に集約
- `init()` — 保存があれば復元、なければ初期配置

## 保存形式（JSON）

自動保存は `localStorage` の `previz-editor.scene.v1`。
「このシーンを保存」で同じ形のファイルが出る。

```jsonc
{
  "version": 2,
  "fps": 24,              // 全カット共通
  "ease": "smooth",       // "smooth" | "linear"
  "autoFace": true,       // 動かしたら進む向きを向く
  "shotIndex": 0,         // いま開いているカット
  "shots": [{
    "name": "カット1",
    "duration": 120,      // コマ数。カットごとに変えられる
    "lookAt": 1,          // 注視している相手（objectsの番号）。なければ null
    "objects": [
    { "type": "camera", "name": "カメラ",
      "keys": [ { "f": 0, "p": {...}, "r": {...}, "lens": 35 } ] },
    { "type": "char", "kind": "human", "name": "レッド", "colorIndex": 0,
      "keys": [ { "f": 0, "p": {"x":0,"y":0,"z":0}, "r": {"x":0,"y":0,"z":0}, "lens": 35 } ] },
      { "type": "prop", "name": "めじるし1",
        "pos": {"x":-8,"y":0,"z":-3}, "ry": 0 }  // めじるしはキーを持たない
    ]
  }]
}
```

**version 1（カットが1つしかなかった頃）の形も読める。** `shots` がなく `objects` が
直下にある場合は、1カットとして取り込む。

- `f` はコマ番号、`p` は位置（メートル）、`r` は回転（ラジアン）
- 座標は右手系。**+Z がキャラクターの正面**、Y が高さ
- `kind` は `human` / `giant` / `dragon`

## 手を入れるときの勘どころ

1. **キーは触った時間のものだけ書く。** ほかの時間のキーを書き換える処理を足さない
2. **見た目の演出は `fx` グループに入れる。** `root` を動かすとデータが汚れる
3. **色は `col()` を通す。** ただしフォグの色だけは通さない
4. **拾うときは見えている面を優先する。** 当たり判定を先に見ると別のものが選ばれる
5. **UIは状態が決まったら選択肢を消す。** 注視中にカメラの道具バーを隠しているのがその例
6. **カットをまたぐ処理は `serializeShot()` で控えてから。** `state.objects` はいま開いている
   カットのものでしかないので、控えずに切り替えると編集内容が消える
