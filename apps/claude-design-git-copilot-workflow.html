🎨 Claude Design × Git Copilot で進めるUIモック作成ワークフロー

「仕様書 → モック → 実装」をAIで効率化する2AI連携フローと、実際に使ったプロンプト

はじめに

WEBアプリ開発において、「仕様書 → モック → 実装」の流れをAIでどこまで効率化できるか試してみました。 ここでは、Git CopilotとClaude Designを組み合わせたワークフローと、実際に使ったプロンプトを紹介します。

🔄 全体の流れ

1

Git Copilotに仕様書を書いてもらう

2

その仕様書をClaude Designに渡してUIモック(HTML/CSS)を作成

3

できたモックをGit Copilotに読ませて、実装に反映

ポイントは、各ステップで「渡す相手に合わせて情報の粒度を変える」ことです。仕様書は実装の詳細を書かず画面の中身に絞り、 モック反映時は逆にプロジェクトの技術スタックを明示する、という使い分けをしています。

📝 使ったプロンプト

実際の流れの順番に並んでいます：①仕様書を書いてもらう → ②モックを実装に反映する。
① Git Copilotに「Claude Design用仕様書」を書いてもらうプロンプト
Claude Designが画面を組み立てやすい形(画面単位・要素単位・状態)で仕様書を出力させるのがコツです。
これから作るWEBアプリの仕様書を、UIモック作成AI(Claude Design)に渡すために書いてください。 以下の構成でまとめてください。 1. アプリの概要と目的(誰が何のために使うか) 2. 想定ユーザーと利用シーン 3. 画面一覧(画面名・役割を簡潔に) 4. 各画面の詳細 - 表示する要素(見出し、ボタン、フォーム項目、リストなど) - ユーザーの操作とその結果(何を押すと何が起きるか) - 画面の状態(初期表示、ローディング中、エラー時、空データ時など) 5. 画面遷移(どの画面からどの画面に移動するか、簡単な図か箇条書きで) 6. トーン・雰囲気の希望(あれば。ミニマル/カジュアル/業務的など) 7. 参考にしたい既存サービスやデザインがあれば明記 実装の詳細(使用フレームワーク、DB設計、API仕様など)は不要です。 あくまで「画面に何が表示され、何ができるか」が伝わる粒度で書いてください。
ポイント： 「実装の詳細は不要」と明示するのが重要です。Copilotは放っておくと技術仕様(API、DB、ライブラリ)まで書き込みがちで、Claude Designにはノイズになります。
② モックをGit Copilotに反映させる時のプロンプト
こちらは逆に、Copilotに「デザインの意図」を正しく汲み取らせる指示が要点です。
添付のHTML/CSS(Claude Designで作成したUIモック)を、このプロジェクトの実装に反映してください。 - モックの見た目・レイアウト・コンポーネント構成をできるだけ忠実に再現してください - ただし現在使用しているフレームワーク/CSS手法([Reactか, Vueか, プレーンJSか]/[Tailwindか, CSS Modulesか, 素のCSSか]など、実際の構成を指定)に合わせて書き換えてください - 既存のコンポーネント([ボタン, カードなど既存の共通コンポーネント名])があれば流用し、モックのクラス名やスタイルをそのまま持ち込まないでください - レスポンシブ対応(該当あれば)やアクセシビリティ(alt属性、aria属性など)も適切に補ってください - 反映後、モックと実装の差分(意図的に変更した箇所)を簡単にまとめてください
[ ] の部分はプロジェクトの実際のスタックに置き換えて使います。特に「既存コンポーネントを流用させる」の一文が抜けると、Copilotがモックのベタ書きCSSをそのままコピーしてきて、後で二重管理になりがちなので注意が必要です。

💡 Claude Designについて

Claude Designは2026年4月にリリースされたAnthropicのデザイン作成ツールで、チャットで指示を出すだけでWebサイトやアプリのUIプロトタイプ、 スライドなどを作成できます。Claudeの有料プラン限定機能で、デスクトップアプリにも対応しています。
作成できるのは画面デザインやプロトタイプといったUI部分のみで、会員登録や決済などのバックエンド機能には対応していません。 本格的な開発に進む際は、Claude Codeへデザインデータを引き継いで実装に移行する流れになっており、双方向同期にも対応しています。

🔍 まとめ

  • 仕様書作成とモック反映では、AIに渡す情報の粒度を変えるのがコツ
  • 仕様書は「画面に何が表示され、何ができるか」に絞る
  • モック反映時は技術スタックと既存コンポーネントの流用を明示する
