ComfyUIを標準UIなし・APIだけで使う話

「自分のタイムラインWebUIからComfyUIを動かしたいけど、標準フロントエンドは使いたくない」—— デザイナーAさんと、ComfyUIに詳しいBさんの対話をまとめました。API利用の考え方から、 ワークフローのAPI形式エクスポート、セキュリティを気にした通信の絞り方まで、実際にやり取りされた内容をそのまま掲載しています。

対話形式 ComfyUI API 公開日 2026.08.18

この記事でわかること

  • 標準UIなし運用は可能 — ComfyUIはサーバーとUIが分離しているため、/promptなどのAPIだけを叩く使い方が普通にできる。
  • 安全性重視なら公式リポジトリのまま — サードパーティのフォークやラッパーを足さなくても、API用途としてはそのまま十分機能する。
  • ワークフローはAPI形式でエクスポート — 「Enable Dev mode Options」→「Save (API Format)」で書き出したJSONをテンプレートとして使い回す。
  • ミュートノードは除外されない — エクスポートには全ノードがそのまま含まれる。ミュートは処理をそこで止めるだけで、除外したいなら自前でプルーニングが必要。
  • 「WebUI」と「フロントエンド」の呼び分け — フロントエンドの方が広い概念、WebUIはブラウザで動くものを指す、という整理で問題ない。
  • ファイアウォールで通信を絞れる — localhost同士の通信は制御対象外なので、python.exeの外部送信だけブロックしても自作WebUIとの連携は生きる。

ComfyUI詳しい人B 🧑‍💻

ComfyUI詳しい人B 🧑‍💻

👩‍🎨 デザイナーA
そのJSON、出力に繋がってないノードとかミュートしたノードは自動で除かれるの？
ComfyUI詳しい人B 🧑‍💻
いや、エクスポート自体は全部そのまま入る。ミュートは「そこで処理が止まる」だけで、Bypassとは違って後続もブロックする。除外はしてくれないから、AIに渡す前提なら自分で軽くプルーニング処理を書くのが現実的。rgthreeとかComfyScriptにも近い発想の機能はあるけどね。
👩‍🎨 デザイナーA

ComfyUI詳しい人B 🧑‍💻
全然普通の言葉だから気にしなくていいよ。強いて言うなら「フロントエンド」の方が広い概念（ブラウザに限らない）で、「WebUI」はその中でブラウザ動作のものを指す、くらいの整理。
👩‍🎨 デザイナーA
じゃあ自分は「ブラウザで動くもの＝WebUI」「単独でも動くアプリ＝フロントエンド」で使い分けるね。
ComfyUI詳しい人B 🧑‍💻
それで十分伝わるよ。
👩‍🎨 デザイナーA

ComfyUI詳しい人B 🧑‍💻
それは有効な方法。localhost同士の通信はファイアウォールの制御対象外だから、外部への送信だけブロックしても自作WebUIとの連携は生きる。python.exeを「送信の規則」でブロックすればいい。
👩‍🎨 デザイナーA
カスタムノードのインストールとかManagerの通信も同じプロセス？
ComfyUI詳しい人B 🧑‍💻

用語整理：WebUI と フロントエンド

フロントエンドサーバー（バックエンド）と対になる、利用者が直接操作する側全般。ブラウザで動くものに限らない広い概念。
WebUIフロントエンドのうち、ブラウザ上で動作するもの。この記事でのタイムライン操作画面は「WebUI」にあたる。
