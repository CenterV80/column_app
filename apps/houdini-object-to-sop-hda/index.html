ObjectレベルのHDAを
SOPレベルに変換する方法

サブネットを組んでDigital Asset(HDA)化するとき、うっかりObject(ジオメトリ)レベルで HDA化してしまい、「本当はSOPレベルの部品として他のネットワークに組み込みたかった」—— これは意外とよくある失敗です。この記事では、その状態から SOPレベルの部品として作り直す2つの方法を図解でまとめます。

1Objectレベルと SOPレベルの違い

Houdiniのネットワークには階層があります。シーンビュー直下の Objectレベルには、ジオメトリノード(geo)やカメラ、ライトといった 「オブジェクト」が並びます。そのジオメトリノードの中に入ると、Box・Transform・Merge… といった実際の形状を作るノード群が並ぶSOPレベルがあります。

📦 Objectレベル（/obj）
🧩 SOPレベル（/obj/geo1 の中）
Box Transform Merge

図1：Objectレベルの中に、SOPレベルのノード群が入れ子になっている

ポイント： HDA化は「その時点でどの階層のノードを選択していたか」によって、 Objectレベルの部品にもSOPレベルの部品にもなります。SOPレベルの部品は他のジオメトリ ネットワークの中に他のSOPノードと並べて置けますが、Objectレベルの部品はそれができません。

2何が問題になるのか

サブネットをまとめて選択した状態でCreate Digital Assetを実行すると、 HDAの「境界」はその時いたコンテキスト(階層)に応じて決まります。Objectレベルで実行すれば HDAはObjectレベルの部品として作られ、他のSOPネットワークの中には組み込めません。

└ Box / Transform / Merge（SOP）

✅ SOPレベルで作り直す
HDAの境界
Box / Transform / Merge（SOP）

他のSOPネットワークに部品として組み込める

注意： HDA化のダイアログでは、コンテキスト(Table)が Sopになっているかを必ず確認してください。ここがObjectのままだと、 せっかく移植してもまたObjectレベルのHDAになってしまいます。

5パラメータの移植手順

パラメータ数が多い場合(数十個規模でも)、以下の流れが現実的です。

1

Type Propertiesごとコピー

元HDAのType Properties → Parametersタブで、フォルダ/パラメータをまとめて選択し Copy Parameters。新HDA側のType Properties → Parametersに Paste Parametersすることで、フォルダ構成ごと一括移植できる。

2

チャンネル参照の確認

パラメータ定義をコピーしても、SOPノード側のch("../param名")のような 参照式は自動では追従しない場合がある。相対パス構造が変わっていないか、 フォルダ単位で確認するとチェック漏れを防ぎやすい。

3

動作確認

HDAをインスタンス化し、各パラメータを実際に動かしてジオメトリが追従するか目視で確認する。 特にモデリング系のHDAでは、Transform・Group・Boolean系のノードが絡むことが多く、 数値のズレが見た目にわかりにくいバグにつながりやすいため、パラメータを極端な値に振って 挙動を確認するのが有効。

4

参照が壊れている場合

式の書き直しではなく、SOPノード側のパラメータを右クリック→Link Parameter... から新HDAのパラメータへ再リンクする方法もある。手間はかかるが、式の記述ミスを避けられる。

まとめどちらを選ぶべきか

方法 向いているケース 手間
方法1：選び直してサブネット化 ノード構成がシンプル 最初からやり直すが手順は少ない
方法2：既存HDAの中身を移植 パラメータを作り込み済み コピー＆ペーストで済むが参照チェックが必要
共通ポイント： どちらの方法でも、HDA化時のコンテキスト指定 (TableをSopにすること)を忘れずに確認するのが重要です。
