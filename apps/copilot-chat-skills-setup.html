🤖 Copilot Chatでスキルを使う手順

VS CodeのGitHub Copilot Chatに「Agent Skills」を読み込ませて、自作の作業手順を呼び出せるようにする

スキル（Agent Skills）は、手順書やスクリプトをフォルダーにまとめておくと、 Copilotが必要になったタイミングだけ読み込んでくれるしくみです。 copilot-instructions.md のように常に読まれるものと違い、 関係のある話題のときだけ読み込まれるので、コンテキストを無駄に消費しません。 ここでは例として、Houdiniのネットワークを HDA 化する手順をまとめた houdini-hda というスキルを作る流れで説明します。

🚀 セットアップの7ステップ

1

VS Codeを最新版に更新する

スキル機能が入ったのはバージョン1.108（2025年12月）から。 「ヘルプ → 更新の確認」で最新にしておきます。
1.108の時点では実験的な機能でしたが、1.109（2026年1月）で既定でオンになりました。 新しめのVS Codeを使っているなら、次のステップ3は基本的に不要です。
2

GitHub Copilot Chat拡張を入れてサインインする

拡張機能ビューから「GitHub Copilot Chat」をインストールし、GitHubアカウントでログインします。
3

スキル機能をオンにする（必要な場合のみ）

設定（Ctrl + ,）で chat.useAgentSkills を検索してチェックを入れます。 すでにオンなら何もしなくてOKです。
4

スキル用フォルダーを作る

VS Codeで開いているフォルダーのいちばん上に、スキル名と同じ名前のフォルダーを作ります。
<プロジェクトのルート>/ .claude/ skills/ houdini-hda/ SKILL.md
置き場所は1か所ではなく、次のどれでも読み込まれます。
種類 置き場所
プロジェクト用（リポジトリに入れて共有する） .github/skills/、.claude/skills/、.agents/skills/
個人用（全プロジェクト共通で使う） ~/.copilot/skills/、~/.claude/skills/、~/.agents/skills/
.github/skills/ がVS Code標準の置き場所で、.claude/skills/ はClaude Codeのスキルをそのまま使えるようにサポートされている場所です。 Claude Codeと共用したいなら .claude/skills/、Copilot専用なら .github/skills/ と使い分けると迷いません。
全プロジェクト共通にしたい場合： 上の表の「個人用」の場所（ユーザーフォルダー側）に作ります。 かつて任意のフォルダーを追加登録できた chat.agentSkillsLocations 設定は現在非推奨なので、 新しく設定するなら決められた場所に置くのが確実です。
5

SKILL.md を作る

先頭にYAMLの見出し（フロントマター）として name と description を書き、 その下に手順やルールを普通のMarkdownで書きます。
--- name: houdini-hda description: HoudiniのノードネットワークをHDA(Digital Asset)化する手順とルール。「HDAにして」「デジタルアセット化して」と頼まれたときや、HDAのパラメータ設計・保存先の相談を受けたときに使う。 --- # Houdini HDA 作成ルール ## 前提 - HDAはSOPレベルで作る。Objectレベルで作らない （他のジオメトリと繋げられなくなるため） - 保存先は プロジェクト直下の `hda/` フォルダー - ファイル名は `<名前空間>_<アセット名>.hda` ## 手順 1. HDA化したいノード群を選択し、`Shift + C` でサブネット化する 2. サブネットを右クリック →「Create Digital Asset」 3. Operator Name / Label / Save to Library を設定する 4. Type Properties でパラメータを整理する 5. 内部パラメータへのリンクが切れていないか確認する ## 注意 - 完成後は必ずシーンを開き直して、ライブラリから読み込めるか確認する
name はフォルダー名と完全に一致させること。 使えるのは英小文字・数字・ハイフンだけで、スラッシュ・コロン・ドットは使えません。 ここが合っていないと、エラーも出ないまま黙って読み込まれないので要注意です。
6

チャットを「エージェント」モードにする

Copilot Chatの入力欄の下にあるモード切り替えで「Agent」を選びます。
スキルはエージェントモード専用ではありません。 公式ドキュメントでも「chat and agent mode」で使えるとされていて、通常のチャットでも読み込まれます。 ただし「読み込まれる」ことと「最後までやってもらえる」ことは別で、 命名規則や設計ルールのような知識・手順を参照するだけのスキルはチャットでもそのまま効きますが、 ファイルの編集やコマンド実行まで書いてあるスキルは、ツールを実際に動かせるエージェントモードでないと途中で止まります。 下の houdini-hda のように「こう作れ」と指示するタイプは後者なので、Agentを選んでおくのが確実です。
なお、1.108より後のVS Codeでは、公式ドキュメントから Ask / Edit / Agent というモード切り替えの説明自体がなくなり、 「チャットビューはエージェントと会話するもの」という前提で書き直されています。 手元のVS Codeに切り替えが残っていればAgentを選ぶ、程度に考えておけば大丈夫です。 また、フロントマターに context: fork を書いて専用のサブエージェントで動かすスキルだけは、 別途 github.copilot.chat.skillTool.enabled の有効化が必要です。
7

読み込まれたか確認する

チャット入力欄で / を打つと、使えるスキルとプロンプトの一覧が出ます。 ここに houdini-hda が並んでいればOK。 /skills と打てば、スキルの有効・無効を切り替える「Configure Skills」メニューが開きます。
呼び出し方は2通りあります。
  • 自分で指名する： /houdini-hda と打つ。うしろに /houdini-hda このサブネットを のように補足を足してもOK
  • 自動で使ってもらう： 「このノードをHDA化して」と普通に頼むだけ。description の内容と話題が合えば、Copilotが自分で読み込みます

🔧 うまく反応しないときは

name とフォルダー名が一致しているか

.claude/skills/houdini-hda/ なら name: houdini-hda。 ここがズレていると読み込まれません。大文字やアンダースコア、 myorg/houdini-hda のような接頭辞も無効です。

description に「いつ使うか」が書かれているか

Copilotは description だけを見て「この話題に使うべきか」を判断します。 「HDA化の手順」とだけ書くより、 「〜と頼まれたときに使う」まで具体的に書いたほうが自動で拾われやすくなります。 自動で拾ってほしくない場合は、あえて /houdini-hda で毎回指名する運用にもできます。

一覧には出るのに中身が効いていない

SKILL.md 以外のファイル（スクリプトやテンプレート）は、 SKILL.md の中からリンクされていないと読み込まれません。 [テンプレート](./template.hip) のように、相対パスのMarkdownリンクで参照しておきます。

📌 補足：instructionsとの使い分け

どちらもCopilotの動きをカスタマイズするものですが、役割が違います。
　 スキル（Agent Skills） カスタム指示（copilot-instructions.md）
目的 特定の作業手順・専門的な進め方を教える コーディング規約や全体のルールを決める
読み込み 関係するときだけ、必要な分だけ 常に適用される
中身 手順書＋スクリプトやサンプルなどのファイル一式 指示文のみ
持ち運び 共通仕様なので他のAIツールでも使える VS Code / GitHub.com向け
スキルは agentskills.io のオープン仕様に沿っているため、 同じフォルダーをGitHub Copilot・Copilot CLI・Claude Codeなどで共有できます。 既製のスキルは github/awesome-copilot や anthropics/skills にまとまっています （中身を確認してから使うこと）。
