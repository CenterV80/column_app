🔗 セッションログ運用ワークフロー：AGENTS.md対応版

ルール定義を .github/copilot-instructions.md から AGENTS.md に移し、Copilot以外のAIでも同じルールでログを書けるようにする

以前のセッションログ運用ワークフローでは、ルール定義を .github/copilot-instructions.md に置いていました。今回はこれをルート直下の AGENTS.md に移し、Copilot以外のAI（Claude Code、Codex、Cursorなど）でも 同じルールでログが書かれるようにします。

🔄 何が変わるか

変わるのはルール定義の置き場所だけです。session-log.md・session-log-archive.md・known-issues.md の3ファイルと、ログのフォーマットや運用タイミングはそのまま使えます。
docs/ session-log.md session-log-archive.md known-issues.md AGENTS.md ← 旧 .github/copilot-instructions.md の中身 CLAUDE.md ← 「@AGENTS.md」の1行だけ

📄 AGENTS.mdとは

AIエージェント向けのREADMEのようなファイルです。OpenAI・Google・Cursorなどが策定したオープン標準で、 特定ベンダーに依存しません。中身は普通のMarkdownで、決まった書式はありません。リポジトリのルートに 置くだけで、Copilot・Codex・Cursorなど多くのツールが読み込みます。

❓ なぜCLAUDE.mdも必要か

Claude CodeはAGENTS.mdを直接読まず、CLAUDE.mdを読みます。そこで、CLAUDE.mdに次の1行だけを書いておきます。
CLAUDE.md
@AGENTS.md
@ で始まる行はファイルの取り込み指定です。これで内容を重複させずに、Claude CodeにもAGENTS.mdのルールが適用されます。

✍️ フォーマットに1行追加（推奨）

複数のAIが同じファイルに書くようになるので、誰が書いたかを残す行を足しておくと後から追いやすくなります。
## [日付] [作業タイトル] - 記録者: （Copilot / Claude Code など） - やったこと: （1〜2行で） - 気づき: （次回に活きる発見。無ければ省略可） - 躓いた点 → 原因 → 対処: - 問題: - 原因: - 対処: - 次回への申し送り: （あれば）

🔧 セットアップ用bat（AGENTS.md版）

@echo off if not exist docs mkdir docs if not exist docs\session-log.md type nul > docs\session-log.md if not exist docs\session-log-archive.md type nul > docs\session-log-archive.md if not exist docs\known-issues.md type nul > docs\known-issues.md if not exist AGENTS.md type nul > AGENTS.md if not exist CLAUDE.md echo @AGENTS.md> CLAUDE.md echo セットアップ完了 pause
📥 session-log-workflow-agents-setup.bat をダウンロード
.github フォルダの作成が不要になり、CLAUDE.mdは参照行入りで作成されます。作成後、AGENTS.md に元記事の「作業ログのルール」を貼り付けてください。

🚚 既存リポジトリの移行手順

1
.github/copilot-instructions.md の「作業ログのルール」を AGENTS.md に移す
2
CLAUDE.md を作り、@AGENTS.md と書く
3
copilot-instructions.md から移したルールを削除する（Copilot専用の指示が無ければファイルごと削除）
両方に同じルールを残さないこと。 Copilotは両方のファイルを読むので、片方だけ更新すると指示が食い違います。
一度に全リポジトリを移す必要はありません。触るタイミングで順番に移し、新規リポジトリは最初からAGENTS.mdで始めれば自然に置き換わります。

💡 設計のコツ（追加分）

  • ルールの実体は1か所だけ：各ツールの設定ファイルは参照するだけにする
  • 記録者を残す：複数AIの運用では、どのAIの判断かが後から重要になる
  • 階層を浅く保つ：ルート直下の短いファイル名なので、コピーや参照の手間が減る

🔍 補足

コンテキストとの関係など、運用の前提は元記事の内容がそのまま当てはまります。詳しくは セッションログ運用ワークフローを参照してください。
