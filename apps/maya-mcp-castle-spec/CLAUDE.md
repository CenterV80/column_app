# 日本の城（白壁・姫路城系）制作プロジェクト

あなたはMaya MCPとComfyUI MCPを使って、参照画像をもとに日本の城（白壁・姫路城系）を作る。
目的は「AIに任せられる作業」と「人が必要な作業」を切り分けること。うまくいかなかった点も成果なので、隠さずに報告する。

## 作業の進め方

- 作業は段階ごとに依頼される。1ステップごとに結果を報告して止まり、次の指示を待つ
- 作業前に必ずシーンを保存する
- 失敗や手直しが必要な箇所は、隠さずに報告する
- 各ステップの最後に評価用カメラで `playblast` を撮影して確認し、問題点を報告する
- 範囲はモデリング、テクスチャ生成と割り当て、瓦配置、ビューポート評価まで。リグ・アニメーション・最終レンダーには手を出さない（素材確認用の低解像度レンダーは可）

## スケールと形状

- 層数・屋根の構成・各部の比率は参照画像に準拠する。段階0で書き出して確認を取った内容に従う
- 単位はcm。天守の高さは参照画像の比率から割り出す（目安は約3000cm）
- 1パーツ＝1メッシュで分ける。ポリゴン数の上限は設けない
- 形は次の順で育てる
  1. 箱組み版：台形の石垣、参照画像と同じ層数の天守（上ほど小さい箱）、各層に寄棟の屋根（壁から少しはみ出す）
  2. 城らしさを足す：参照画像に見える屋根の反り、入母屋・千鳥破風、窓
  3. 仕上げ：石垣の反り（扇の勾配）、鯱などの装飾。できなければ限界として報告する

## 命名とフォルダ

| 対象 | 命名 | 例 |
| --- | --- | --- |
| メッシュ | `castle_{部位}_geo` | `castle_roof01_geo` |
| 瓦の元モデル | `castle_tile_{maru\|hira}{01-03}_geo` | `castle_tile_maru02_geo` |
| マテリアル | `castle_{素材}_mtl` | 素材は stone / plaster / wood / tile01〜03 |
| テクスチャ | `castle_{素材}_{albedo\|height\|rough}.png` | `castle_stone_albedo.png`、`castle_tile02_rough.png` |

- テクスチャは `project/textures/` に保存する（Mayaプロジェクトのsourceimagesに指定済み）
- 評価ログ（各回の画像・項目別の点数・修正内容）は `project/log/` に保存する

## マテリアルとUV

- シェーダーは `aiStandardSurface` で統一し、Arnoldで確認する
- 接続：Albedo → `baseColor`、Height → `bump2d` → `normalCamera`、Roughness → `specularRoughness`
- 石垣・白漆喰・木部のUVは、テクスチャ1枚＝実寸2m四方で1タイルになるように合わせる
- 瓦には2mタイリングを使わない。瓦モデルのUVを0〜1に収め、テクスチャ1枚を瓦1枚に貼る

## テクスチャ生成（ComfyUI MCP）

- 指定できる入力はプロンプト（可変部分）、シード、出力名、解像度の4つのみ
- 固定プロンプトはワークフロー側に入っているので、可変部分だけを渡す
- 瓦は同じプロンプトでシードだけを変えて3種類（tile01〜03）生成する
- 生成後はAlbedo・Height・RoughnessのTile PreviewとSeam Heatmapを確認し、継ぎ目が出ていれば報告する
- 素材ごとの可変プロンプト

| 素材 | 可変プロンプト |
| --- | --- |
| stone（石垣） | `Japanese castle stone wall, tightly fitted granite blocks, uchikomi-hagi style, weathered gray stone, moss in the gaps` |
| plaster（白漆喰） | `white Japanese plaster wall, smooth lime plaster, subtle stains and faint weathering` |
| wood（木部） | `dark aged wood, Japanese castle timber, straight vertical grain` |
| tile01〜03（瓦1枚の質感） | `dark gray fired clay surface, Japanese roof tile, subtle glaze and weathering` |

## 瓦の配置

- 瓦はテクスチャではなく1枚ずつのジオメトリにし、Pythonの配置ツールで並べる
- 配置には**instancerノード**を使う。複製や、瓦1枚ごとのインスタンスノードは作らない（数千〜数万枚になるため）
  - 屋根面上の配置点をnParticleで作り、各点に位置・回転・objectIndexを持たせる
  - instancerには瓦の元モデル（丸瓦・平瓦×3バリエーション）を登録し、objectIndexでどれを置くかを決める
- 色ムラは、元モデルごとにtile01〜03のマテリアルを割り当てておき、objectIndexをランダムに振って出す
- 丸瓦と平瓦から始める。余裕があれば軒瓦（巴紋）と棟瓦を追加する
- 屋根面の勾配方向に列を作り、平瓦と丸瓦を交互に並べる
- パラメータ：列の間隔、重なり量、ランダム回転、ランダム位置ズレ、バリエーションの割り振り。乱数はシード指定で再現できるようにする
- 平面屋根で動かしてから、反った面に沿わせて法線に合わせて向きを変える形に広げる
- まず屋根1面で試し、問題なければ全屋根に適用する
- パラメータを変えて再配置でき、他の屋根にも使えるツールとして残す
- 配置後は各瓦と屋根面の距離をレイキャストで測り、許容値（0.5cm）を超えた瓦をリストにして報告する

## 評価と再現ループ

### カメラと撮影

- 評価用カメラは固定5台：正面、側面、俯瞰、斜め45°、軒先アップ
- 加えて参照画像と同じ構図のカメラ1台。参照画像から焦点距離・カメラの高さ・向きを推定し、人の確認を取ってから固定する
- 撮影は `playblast` で1フレームをPNG出力する（Maya MCPにキャプチャ機能があればそれを使う）
- 「素材感・色」の採点だけは、参照構図カメラでArnoldの低解像度レンダー（960×540程度）を使う

### 採点

- 5項目×10点（合計50点）。目安は次のとおり

| 項目 | 3点 | 6点 | 9点 |
| --- | --- | --- | --- |
| シルエット | 輪郭が別物 | 大まかな輪郭は合うが、層や屋根の数・位置がずれる | 参照と重ねてもほぼ一致 |
| プロポーション | 石垣・各層の高さの比が明らかに違う | 一部の層の幅・高さがずれる | 各部の比率が参照と一致 |
| 屋根の形と反り | 寄棟の直線のまま | 反り・破風はあるが、形や位置が参照と違う | 軒先の反り上がりと破風の配置が参照と一致 |
| 瓦の並び・密度 | 浮き・隙間・向きの乱れが目立つ | 並びは揃うが、密度や重なりが参照と違う | 列・重なり・密度が自然で破綻がない |
| 素材感・色 | 素材の区別がつかない | 素材は分かるが、色味や汚れ方が参照と違う | 白壁・石垣・瓦の色と質感が参照に近い |

- 採点は自分で行わず、修正の経緯を渡さないサブエージェントに、参照画像・撮影画像・上の基準表だけを渡して行わせる
- 画像で見るチェック項目
  - 瓦の浮き・めり込み、向きの逆転、列のずれ、隙間
  - テクスチャの継ぎ目や引き伸ばし
  - 全体のプロポーション
- 全体の見た目は画像、細かい精度（瓦の浮きなど）は数値チェックで判断する

### ループと停止条件

- ループは「制作 → 撮影 → 比較 → 採点 → 修正」
- 40点以上で完了
- 前回より合計+2点以上を「改善」とみなす。+2点未満が3回続いたら停止して報告する
- 最大10回で停止して報告する
- 修正案を出したら、人の確認を待ってから再制作する
- 点数は参考値として扱い、最終判断は人に委ねる

## 報告

報告では「AIだけでできた作業」と「人の手が必要だった作業」を分けて書く。あわせて次を残す。

- 問題を見つけたのがAIか人か
- ループの回数ごとの点数推移（項目別）
- 瓦配置ツールを他の屋根でも再利用できるか
